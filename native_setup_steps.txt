Run these in AndroidIDE's terminal, from your project root.

1. Add llama.cpp as the inference engine source:

   mkdir -p app/src/main/cpp
   cd app/src/main/cpp
   git clone --depth 1 https://github.com/ggerganov/llama.cpp.git

2. Pull the actual JNI bridge from Hugging Face's own Android reference
   (this is the piece I will NOT hand-write from memory - get the real,
   tested source):

   git clone --depth 1 https://github.com/huggingface/smollm.git /tmp/smollm-ref

   Inside /tmp/smollm-ref, look for their Android example (path may be
   something like smol_chat_android/ or android/ depending on current repo
   layout - browse it in a file manager if the terminal listing is unclear).
   Copy these specific things into your project:

     - Their JNI bridge .cpp file (the one exposing loadModel/generate/free
       via JNIEXPORT functions)  ->  app/src/main/cpp/llama_bridge.cpp
     - Their CMakeLists.txt (adapt paths to match your folder names)
                                    ->  app/src/main/cpp/CMakeLists.txt
     - Their Kotlin/Java wrapper class declaring the `external`/`native`
       functions matching that bridge - use this to get the EXACT method
       signatures right, even if you end up rewriting it in Java (Stage 2
       below assumes specific signatures - adjust to match whatever you
       actually pull in)

3. Delete /tmp/smollm-ref once you've copied what you need - it's just a
   reference, not part of your project.

Why this specific approach: llama.cpp's C API has changed across versions
(function names, struct layouts), and a JNI bridge has to match the exact
version you're building against. Hugging Face's own reference is kept in
sync with a specific llama.cpp commit, tested on real devices, and mirrors
the exact model format you're using (GGUF, SmolLM family) - so copying it
verbatim and adapting file paths is far more reliable than a bridge
generated from general knowledge of the API.
