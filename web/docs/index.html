Overview

PhoneServer exposes its storage, project, file, token, and mail features over a local HTTP API. The server runs on the device on fixed port 8080. The versioned data API is served under /api/v1.

Security boundary: everything under /api/v1 requires authentication except GET /health. Use a bearer token for applications and scripts. Passwords and private mail content are never returned by list endpoints.

Quickstart

  1. Start PhoneServer and keep the device on the same network as your client.
  2. Create an API token from the app, or use the access password for admin tasks.
  3. Call GET /api/v1/health to confirm the server is reachable.
  4. Call GET /api/v1/ for the live endpoint index.
curl http://<device-ip>:8080/api/v1/health

curl -H "Authorization: Bearer $TOKEN" \
  http://<device-ip>:8080/api/v1/

Email setup

PhoneServer connects to an external SMTP/IMAP provider, such as a VPS mail server or hosted mailbox. It does not publish SMTP or IMAP ports itself.

Add an account in the app

  1. Open Mail from the navigation drawer, then tap Accounts.
  2. Tap New account and enter the email address, login username, password or app password, SMTP settings, IMAP settings, and folder names.
  3. Use starttls with SMTP port 587 or tls with port 465; use IMAP port 993 with tls.
  4. Tap Save. PhoneServer performs real SMTP and IMAP logins before saving the account.
  5. Return to Mail, then tap Sync, Search, or Compose.

Certificates: use a public CA certificate whose hostname matches the SMTP and IMAP hosts. Self-signed certificates, POP3, OAuth2, and unencrypted mail connections are not supported.

Authentication

A bearer token is the recommended credential:

Authorization: Bearer pst_...

Admin password access is also accepted for compatible clients:

X-Auth-Password: <password>

HTTP Basic and ?pw=<password> are supported by the data API. If no password is configured, anonymous admin access is refused and a token is required.

Token permissions

Token policies support projects.read, projects.write, databases.read, databases.write, files.read, files.write, backups.read, backups.write, system.read, tokens.manage, mail.read, and mail.write. Admin tokens have every permission; editor tokens include mail read and write.

Errors and limits

Errors are JSON: {"error":"message","status":code}. Common statuses are 401, 403, 404, 405, 413, and 429. Requests are rate limited per client IP and, for tokens, per token id.

API reference

Paths below are relative to /api/v1. They are derived from the implemented dispatchers.

Mail API

PhoneServer can connect to an external SMTP/IMAP provider that you control or subscribe to. It does not advertise itself as a public mail server. Credentials are encrypted with the Android Keystore; passwords are never returned by an API response or written to logs.

Required account settings

  • Account name, email address, and login username
  • SMTP host, port, and security: tls or starttls
  • IMAP host, port, and security: tls or starttls
  • Sent and drafts folder names

Account lifecycle

curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"VPS mail","email":"me@example.com","username":"me@example.com","password":"APP_PASSWORD","smtpHost":"smtp.example.com","smtpPort":587,"smtpSecurity":"starttls","imapHost":"imap.example.com","imapPort":993,"imapSecurity":"tls"}' \
  http://<device-ip>:8080/api/v1/mail/accounts

curl -X POST -H "Authorization: Bearer $TOKEN" \
  http://<device-ip>:8080/api/v1/mail/accounts/<id>/test

curl -X POST -H "Authorization: Bearer $TOKEN" \
  -d '{"limit":50}' \
  http://<device-ip>:8080/api/v1/mail/accounts/<id>/sync

Send and read

curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"to":"you@example.net","subject":"Hello","text":"Sent from PhoneServer"}' \
  http://<device-ip>:8080/api/v1/mail/accounts/<id>/send

curl -H "Authorization: Bearer $TOKEN" \
  'http://<device-ip>:8080/api/v1/mail/accounts/<id>/messages?folder=INBOX'
Limits: search is over the local mail cache; message bodies are capped during download; local drafts are stored on the device; appending a copy to the IMAP Sent folder is best-effort and never reverses a successful SMTP send.
